上一篇讨论了 VLA 的运行时智能——如何检测失败并恢复。但”检测到失败”和”保证安全”是不同层次的问题。失败检测回答”是否正在失败”；安全层要求更严格地回答”这个动作是否允许执行”。

本文分析 VLA 安全体系的三层防护，并在最后综合 82 篇论文总结整个系列的八条核心研究主线。

1. 训练时安全：约束学习

SafeVLA

SafeVLA 将安全约束纳入 VLA 的训练过程：

在标准的动作预测 loss 之上，增加 safety constraint loss，使模型在训练阶段就学会避免危险动作。

这是最”内化”的安全方案——安全不是外挂的检查器，而是模型本身的一部分。但它依赖于训练数据中有充分的安全/危险标注。

2. 推理时安全：即插即用安全层

VLSA

VLSA 在 base VLA 与执行端之间加入 plug-and-play safety constraint layer：

VLA 输出动作 → Safety Layer (过滤/修正) → 执行器

优点是：

  • 不修改 base VLA，可以在任何 VLA 上即插即用
  • 安全约束可以独立更新，不需要重新训练整个模型
  • 符合”冻结先验 + 外部模块”的架构范式

3. 控制理论安全：硬约束保证

这一层来自经典控制理论，提供形式化的安全保证。

3.1 Shielding

Shielding（AAAI 2018） 在 action 执行前阻止或修改违反安全规范的动作：

Shield 维护一个安全规范（通常用时序逻辑或有限自动机表达），每个 action 在执行前都经过 shield 检查。

3.2 CBF-QP：控制屏障函数

CBF-QP 提供了连续空间中的安全投影：

通过 Control Barrier Function + Quadratic Programming，将 nominal action 投影到安全集合。

learned_action → CBF-QP → safe_action
                  ↑
            安全约束 h(x) ≥ 0

任何学习策略输出的动作，都会被实时投影到满足 barrier constraint 的最近可行动作。

3.3 Predictive Safety Filter

Predictive Safety Filter 更进一步：

提前预测未来 constraint violation，并在危险发生前修改 learning controller 的 action。

不是等到动作执行时才检查，而是预测”如果执行这个动作，N 步之后会不会进入危险状态”。

3.4 Verified Simplex

Verified Simplex 实现了双层安全架构：

高性能 Learned Controller (正常使用)
        ↓ (安全监测)
Verified Fallback Controller (紧急接管)

当高性能但不可验证的学习控制器可能违反安全约束时，系统自动切换到经过形式化验证的保守控制器。

4. 安全基础综述

Safe Learning in Robotics（Brunke et al., 2022） 提供了 safe learning 和 safe control 的系统性基础，涵盖：

  • Safe exploration（安全探索）
  • Constrained optimization（约束优化）
  • Barrier-based methods（屏障方法）
  • Reachability analysis（可达性分析）
  • Probabilistic safety（概率安全）

5. 未来 VLA 系统的安全架构

综合以上工作，未来的 VLA 系统很可能是：

┌─────────────────────────────────────────┐
│           Learned VLA Policy            │
│    (frozen or periodically updated)     │

               ↓

6. 全系列总结：82 篇论文的八条核心研究主线

A. 时间从数据问题扩展到系统问题

supervision temporal alignment → runtime latency → execution commitment → execution-time verification

B. “当前观测就是状态”正在失效

BridgeVLA++、FM-VLA 支持历史信息的必要性。但 State-free Policy 警告：额外输入可能只是 shortcut。核心问题是：当前决策究竟缺什么信息？

C. 从视觉动作生成器到物理反馈控制器

触觉融合已从”加一个 token”发展为五条完整的融合路线，涉及数据、表示、记忆、反应、预测和监督位置的系统设计。

D. 表示本身成为独立研究变量

不仅”用什么表示”重要（视觉/动作/触觉/行为/意图），“监督施加在哪一层”也会显著改变结果。

E. 冻结先验 + 外部特化已成范式

PriorVLA、RL²-VLA、RLT、Harness VLA 都证明：新能力可以在冻结 base policy 后通过外部模块加入。但 G0.5 提供了重要反方向：统一自回归。

F. 固定开环执行正在消失

RTC 异步生成、BCP 每步决策、CheckVLA 持续验证、ReTouch 在线更新——系统越来越少采用”一次预测后执行到底”。

G. 失败轨迹从废数据变为训练资源

RedFlow 的 action-level correction 和 CycleVLA 的 proactive recovery 证明：失败数据中大量信息仍可被利用。

H. Runtime intelligence 与 safety 分层

Runtime intelligence（precondition → uncertainty → verification → failure detection → recovery）提高任务可靠性；Safety（constraint → shield → fallback → verified controller）提供执行边界。两者是互补而非替代的关系。
