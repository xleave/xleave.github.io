VLA 模型从训练到部署的过程中，时间是一个被严重低估的维度。模型看到的画面是”过去”的，模型计算需要时间，而机器人需要在”未来”执行动作。这种时间错位是 VLA 实际部署中最核心的系统挑战之一。

本文梳理 12 篇论文构成的完整时间主线。

1. 起点：Action Chunking 为什么有效

Action Chunking（ACT）一次预测多步动作而非单步，这已被广泛采用。但它为什么有效？

Why Does Action Chunking Improve BC? 给出了理论分析：

Action Chunking 的大量收益来自 non-Markovian expressivity（表达超越马尔可夫假设的时间依赖）和较低的 compounding error（误差累积）。

此外，chunk 还带来 implicit ensembling 效果——多步预测天然对噪声有平均化作用。

但早在 2021 年，Derman et al. 就已经指出：

Delay 会改变 optimal policy 结构。即使不扩充状态空间，最优 Markov policy 也可能必须是 non-stationary 的。

2. 推理延迟：模型在算，世界在变

2.1 World Model 补偿

RL from Delayed Observations 提出用 world model 与 observation history 恢复更接近当前时刻的 latent state。思路是：虽然你只看到了 100ms 前的画面，但可以用世界模型”脑补”到现在。

2.2 RTC：异步 Chunk 生成

RTC（Real-Time Execution of Action Chunking Flow Policies） 提出了工程上最实用的方案：

时间 →  ──────────────────────────────
执行层:  [chunk_1 执行中] [chunk_2 执行中]
推理层:     [chunk_2 生成中]  [chunk_3 生成中]

冻结已确定执行的 prefix，对剩余部分做 flow/diffusion inpainting，实现异步流水线。

2.3 DEFLECT：反事实偏好对齐

DEFLECT 用 fresh/stale conditioning 构造 counterfactual preference——在同一状态下，分别用”新鲜”和”过时”的观测生成动作，然后训练模型偏好新鲜条件下的输出。这让 VLA 对 inference delay 更鲁棒。

2.4 FutureRTC 与 VLASH：预测执行时的状态

FutureRTC 和 VLASH 采用了类似策略：

先预测真正 execution-time 的视觉表示和 state，再据此生成动作。

这从根本上解决了”我看到的是过去，但要执行在未来”的错位。

2.5 系统实证

World Action Models in Real Time 的实证研究指出：

真正的核心不是某个组件的延迟，而是 observation、prediction、command execution 三者的时间对齐。

3. 自适应执行：一个 Chunk 该相信多久

即使异步推理解决了延迟问题，还有一个更深层的问题：一个预测的动作序列，执行到第几步就应该停下来重新规划？

3.1 AutoHorizon：利用注意力估计可信边界

AutoHorizon 利用 action self-attention 的分布模式估计 chunk 的可靠边界：

当后续 action token 对前面 token 的注意力显著衰减时，说明模型对后续动作的”信心”在下降。

在 test time 动态决定执行长度，而不是固定执行完整个 chunk。

3.2 A3：轨迹共识

A3（Dynamic Execution Commitment） 基于多次 action sampling 的 trajectory consensus：

  • 从模型中采样 N 条轨迹
  • 找到所有轨迹一致的最长 prefix
  • 只执行这个可信 prefix

3.3 BCP：每步决策 Continue or Replan

BCP（Bernoulli-Continuation Policy） 更激进——在每一步用 RL 训练一个二元决策：

继续执行当前 chunk 还是 立即重新规划？

RL 的奖励同时考虑任务成功率和重规划成本，找到最优的”打断频率”。

4. 执行时验证：现实是否按预测发展

CheckVLA 在时间主线上完成了最后一环：

用 action-conditioned world model 检查真实 observation 是否按预测发展。当真实观测偏离预测时，中断当前执行并修复后续 suffix。

这不是简单的”检测失败”，而是持续性的 execution-time verification。

5. 完整时间主线

这 12 篇论文构成了一条清晰的时间主线：

supervision temporal alignment (为什么 o_t → a_t 不对)
        ↓
runtime latency (模型计算时世界在变)
        ↓
asynchronous execution (异步流水线补偿)
        ↓
execution commitment (chunk 该信多久)
        ↓
execution-time verification (执行中持续校验)

必须区分的两种 Delay

  • Delayed Policy 的 delay：示教/策略中 observation→action 的 temporal dependency
  • Inference-execution latency：模型计算引起的推理-执行时间差

前者是数据和学习的问题，后者是系统工程的问题。
